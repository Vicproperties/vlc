# Security Risk Register

Living document. Each stage adds reviewed risks. Nothing here claims the system is fully secure.

| ID    | Risk                                                                                                               | Stage found | Status                  | Mitigation / notes                                                                                                                                                                                            |
| ----- | ------------------------------------------------------------------------------------------------------------------ | ----------- | ----------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| R-001 | Service-role key could leak into client bundle                                                                     | 2           | Mitigated               | Server-only env module guarded by `server-only`; build output scanned for key names. Re-check every stage.                                                                                                    |
| R-002 | Strict CSP may block legitimate embeds (YouTube, Turnstile)                                                        | 2           | Open                    | Baseline CSP in Stage 2; add explicit sources per integration as they are introduced. Nonce-based script CSP to be evaluated in Stage 4.                                                                      |
| R-003 | Service role can technically modify append-only logs                                                               | 1           | Accepted                | Service-role usage restricted to audited modules; optional nightly log export for tamper evidence (Stage 12).                                                                                                 |
| R-004 | Supabase built-in email is not production-grade                                                                    | 1           | Planned                 | Resend configured as custom SMTP in Stage 4.                                                                                                                                                                  |
| R-006 | `npm audit`: 16 moderate advisories in ESLint's dependency chain (`minimatch`)                                     | 2           | Accepted                | Dev tooling only; not shipped to browsers or the server runtime. Re-audit each stage; upgrade when `eslint-config-next` releases a fix. Do not use `npm audit fix --force` (breaking downgrade).              |
| R-007 | HSTS without `preload`                                                                                             | 2           | Planned                 | Add `preload` and submit to hstspreload.org only once the production domain and all subdomains are confirmed HTTPS-only (Stage 12).                                                                           |
| R-008 | Admin shell reachable before auth exists                                                                           | 2           | Mitigated               | `/admin` and `/design` return 404 in production builds (verified by e2e). Replaced by `requireAdmin()` in Stage 4.                                                                                            |
| R-005 | Legal text (Privacy, Terms, cookies) not legally reviewed                                                          | 1           | Open                    | All legal content flagged `needs_legal_review` until a lawyer signs off (NDPA 2023).                                                                                                                          |
| R-009 | Development database password was printed in a session log (malformed .env.local was shell-sourced)                | 3           | **Open — owner action** | Owner to reset the dev database password and update SUPABASE_DB_URL. All env access now goes through scripts/with-env.mjs, which redacts secrets; shell-sourcing .env files is prohibited (docs/database.md). |
| R-010 | Owner-privileged public read views flagged by Supabase Security Advisor (security_definer_view)                    | 3           | Accepted                | Deliberate design (ADR-001): explicit column lists, WHERE clause is the access rule, verified by test:rls.                                                                                                    |
| R-011 | Integration-test DB connection uses ssl rejectUnauthorized=false                                                   | 3           | Accepted (dev only)     | Test cleanup only, dev project only (suite refuses other projects). Production tooling must pin the Supabase CA.                                                                                              |
| R-012 | Admin sessions rely on Stage 4 code to call admin_session_touch; otherwise admins are logged out after 30 min idle | 3           | Planned                 | Stage 4 touches the session on each admin request. Fails safe (locks out, never grants).                                                                                                                      |
| R-013 | Security-definer functions callable by authenticated (my_admin_permissions, log_activity)                          | 3           | Accepted                | Both verify is_verified_admin internally; tests prove customers get nothing.                                                                                                                                  |
